# Подключение базы и писем

Код подготовлен; создание аккаунтов, таблицы и добавление секретов нужно выполнить перед публикацией. Без настроек форма показывает сообщение «Отправка пока не настроена» и не сохраняет почту.

## 1. Supabase — база участников

1. Создайте проект на https://supabase.com/dashboard и сохраните пароль базы у себя.
2. Откройте **SQL Editor → New query**. Вставьте содержимое `supabase/setup.sql`, нажмите **Run**.
3. В настройках проекта найдите **Project URL** и серверный ключ **service_role** (Legacy API Keys). Они понадобятся для Vercel. Не вставляйте серверный ключ в `app.js`, HTML или чат.

В **Table Editor → quiz_submissions** появятся прохождения: email, персонаж (`result`), дата, согласие на рассылку (`marketing_consent`) и статус письма. `pending` означает, что запись сохранена, но отправка ещё не подтверждена; `accepted` — почтовый сервис принял письмо, что само по себе не подтверждает доставку во входящие. Один человек может пройти квиз несколько раз; таблица хранит прохождения. Галочки подписки на рассылку в текущем интерфейсе нет: новые прохождения передают `marketing_consent = false`. Поля подписки сохранены в схеме для совместимости; рассылка не запускается.

Таблица закрыта для посетителей: чтение и запись выполняются сервером. Не отключайте RLS и не добавляйте публичную политику чтения.

## 2. Resend — отправка результата

1. Создайте аккаунт на https://resend.com.
2. В **API Keys** создайте ключ с правом отправки. Храните его только в настройках сервера.
3. Для проверки на собственную почту аккаунта Resend можно использовать отправителя `Деньги и характер <onboarding@resend.dev>`.
4. Для писем реальным участникам откройте **Domains**, добавьте свой домен и подтвердите его DNS-записями, которые покажет Resend. После подтверждения используйте адрес на этом домене, например `Деньги и характер <quiz@your-domain.ru>`. Адрес сайта `financial-character-quiz.vercel.app` не является вашим почтовым доменом.

## 3. Vercel — соединить всё с квизом

В проекте **financial-character-quiz → Settings → Environment Variables** добавьте четыре значения из `.env.example`:

| Имя | Значение |
| --- | --- |
| `SUPABASE_URL` | Project URL из Supabase |
| `SUPABASE_SERVICE_ROLE_KEY` | Серверный service_role ключ |
| `RESEND_API_KEY` | Ключ отправки из Resend |
| `EMAIL_FROM` | Имя и адрес отправителя, см. выше |

Добавьте их в окружения, где будете проверять квиз (Production и, если нужен, Preview). Затем опубликуйте подготовленный код заново. Команда сборки не нужна: фронтенд статический, обработчик `/api/submit-quiz` работает как Vercel Function. Прямое открытие `index.html` позволяет посмотреть интерфейс, но для отправки нужен Vercel либо `vercel dev` с переменными окружения.

## 4. Проверка перед запуском

Пройдите 10 вопросов: должна появиться форма без персонажа. Укажите свой email, отметьте обязательное согласие, отправьте форму. Проверьте одновременно запись в Supabase и письмо с правильным персонажем. Проверьте папку «Спам». Проверьте кнопку «Поделиться»: системное меню отправки или копирование ссылки. При повторной попытке после сбоя используется тот же идентификатор отправки; защита Resend от дублирования действует 24 часа. Через 23 часа незавершённая отправка с прежним идентификатором блокируется.

Результат рассчитывается на сервере по ответам; сами ответы в базе не хранятся. Защита ограничивает новые записи: 3 на email и 20 на хеш IP за час. Это базовое ограничение для прототипа, не полноценная защита от ботов. Хеш IP используется только для ограничения запросов. Для массового запуска можно дополнить форму CAPTCHA.

Тексты галочек — черновик интерфейса. Перед сбором реальных адресов укажите владельца базы и добавьте ваши условия обработки данных и контакты для удаления адреса. Техническая реализация не подтверждает соответствие требованиям конкретной юрисдикции.

Проверка обработчика без реальных писем: `node --test tests/submit-quiz.test.cjs`. Проверяет сохранение до отправки, проверку входных данных, сбои, повторную отправку и ограничения доступа; реальный Supabase и доставку писем нужно проверить отдельно после подключения аккаунтов.

Документация: https://supabase.com/docs/guides/database/postgres/row-level-security и https://resend.com/docs/api-reference/emails/send-email.
